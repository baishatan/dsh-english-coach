# 英语教练 · 设计文档

> 状态：已实现并跑通端到端路径（2026-10-20）。本文保留设计时的判断与理由；实现中修正的细节见 §15。
> 术语以 [GLOSSARY.md](GLOSSARY.md) 为准；本文只解释"为什么这样设计"，不重复定义。

---

## 1. 一句话

**每天自动准备一课，不学的时候随时点几张卡复习，每周看一眼自己有没有真的在进步。**

它替代的不是"背单词 App"，而是那件每天要花二三十分钟的杂活：找一篇难度合适的文章、确认没学过、抠出值得记的表达、出题、排复习。

## 2. 边界

**做**：

- 判断水平并给出一个可理解的说法（六个中文档位 + 一句参照）。
- 维护一份看得见的路线（大纲），每天滚出一课。
- 每天自动找素材、加工成一课，等你确认才展开。
- 复习队列：单词与整块表达，按遗忘曲线的间隙排期。
- 碎片化的卡片，长文交回主面板。
- 进度：掌握数、连续天数、水平曲线。

**不做**（都是刻意的）：

- 不做口语评分。首版没有可靠的发音评估，做不好只会打击信心。
- 不生成图片与视频。平台没有图像/视频生成能力，也不打算接第三方付费服务。
- 不做多账号。一次安装 = 一个学习者。
- 不做排行榜、社交、打卡分享。
- 不声称与任何外部考试分数等价。
- 界面上不出现欧洲语言共同参考框架的分级名称（项目决策）。内部量表仍在，另有一层显示映射。

## 3. 平台约束（已核实）

| 事实 | 后果 |
|---|---|
| 有持久化调度服务 `ctx.schedule`，支持 daily/cron，重启后仍在，漏跑只补最近一次 | 每日任务用它，不用裸定时器 |
| 桌面端是唯一宿主，没有系统级守护进程 | 关着就不跑，只能"下次打开补跑" |
| 没有隐身会话，调度投递不能进入不可见会话 | 每天必然留一个可见会话，见 ADR-0003 |
| 无人值守时审批 fail-closed | Agent 不写文件，见 ADR-0001 |
| 没有图像生成、视频生成、语音合成服务 | 视觉靠 SVG/CSS，声音靠浏览器语音合成 |
| 有语音转文字服务 | 但首版不用（不做口语评分） |
| 内置抓取器会拒绝部分域名（含微信公众号） | 素材获取以搜索驱动为主，抓不到就换源 |
| BBC Learning English、VOA 可访问；British Council 从当前网络不可达 | 偏好源清单不能当唯一来源 |
| 没有可以随插件分发的分级别四选一题库 | 锚题自制，见 ADR-0002 |

## 4. 架构

```
┌──────────────── Host 插件（english-coach）────────────────┐
│  apply(ctx)                                               │
│   ├─ ctx.tools.register × 5        Agent 的读写口          │
│   ├─ ctx.systemPrompt.context      注入学习者状态摘要        │
│   ├─ ctx.schedule.create           每日生成任务              │
│   ├─ Remote 方法                   面板与悬浮层的数据通道     │
│   └─ 存储层                        ~/DeepSeek-English/     │
└───────────────────────────────────────────────────────────┘
                    ↕ Remote
┌──────────────── Client 插件 ───────────────────────────────┐
│  main       今日 / 单词 / 计划 / 个人 四视图工作台            │
│  overlay    药丸 → 待复习数 + 下一个词 + 跳转面板             │
│  settings   学习节奏、时间点、音频来源、数据目录             │
└───────────────────────────────────────────────────────────┘
```

**为什么是 Host + Client 两半**：数据、调度、工具都在 Host；界面在 Client。两层只通过 Remote 方法与工具通信，没有共享内存。

**为什么不需要 `tool.call.toolview`**：Agent 的产物通过面板呈现，不需要在对话流里渲染自定义卡片。少一个渲染面，少一类 bug。

## 5. 数据布局

```
~/DeepSeek-English/
├── profile.json          画像
├── level.json            最新水平估计 + 历史点
├── syllabus.json         大纲（阶段与本阶段目标）
├── progress.json         完成日期（连续天数由它算出）、过期草稿数
├── review/
│   ├── items.json        复习项与盒子状态
│   └── log.jsonl         每次作答
├── anchors/
│   ├── items.json        12 道锚题，冻结，含 SHA-256
│   └── responses.jsonl   锚题作答（重复暴露标记为污染）
├── assessments/
│   ├── bank-<version>.json        一套题库
│   └── <日期>-<kind>-<id>.json    一次测评与它的作答
├── lessons/
│   ├── 2026-10-20.json   结构化（面板渲染用；碎片卡与复习项都在同一文件里）
│   └── 2026-10-20.md     正文（人读用）
└── sources/
    └── provenance.jsonl  每份被采纳素材的来源、抓取时间、许可
```

**为什么是文件不是数据库**：可见、可备份、可 git、出问题能手改、换机器直接拷走。代价是并发写入要自己护住——单学习者场景下这不是问题。

**所有写入只经过插件**（ADR-0001）。Agent 通过工具提交结构化内容，插件校验后落盘。

## 6. 领域对象与状态

**课程状态机**

```
草稿(draft) ──用户点开始──> 进行中(active) ──学完最后一项──> 已完成(done)
   │
   └──当天结束仍未开始──> 过期(expired)
```

`草稿` 不算学过。这是"生成"与"学习"唯一的区别标记，进度统计只认 `done`。

**复习项状态机**

```
新 ──答对──> 1天盒 ──答对──> 7天盒 ──答对──> 30天盒 ──答对──> 掌握
      ↑            │           │            │
      └──答错──────┴───────────┴────────────┘   （任何一盒答错都退回新）
```

掌握之后进入 90 天抽检；抽检答错则回到 30 天盒。

**水平估计**：每次测评产出一个新点，写入 `level.json`。旧的估计不删除——曲线需要它们。

## 7. 用户流程

**首次（一次性）**

1. 引导问卷：想用英语做什么、每天能挤出多久、目标档位。
2. 插件从当前工作区推断一份画像草稿（项目文件、git 记录、近期会话），问一句"这样理解对吗"。
3. 开始测评：20 道自适应选择题（含 3 道锚题），约 8–10 分钟。
4. 给出档位 + 依据 + 薄弱环节，附一句档位参照。
5. 确认后生成大纲。

**每天**

1. 到了设定的时间点，调度服务把任务投给专用会话，Agent 搜索、筛选、加工。
2. 插件落盘一份**草稿**。
3. 药丸变成"今日课程已就绪"，点开是几张短卡：今天的核心表达、两道热身题。
4. 短卡看完，提示"长文在主面板打开"；不想开就明天再说，草稿不催。
5. 打开主面板 → 今日视图 → 逐项完成 → 状态转 `done`。

**碎片时间（任何时刻）**

药丸常驻。点开就是到期复习的碎片卡，一张一张点，四选一，答完自动翻面给讲解。两三分钟能清掉一批。

**每周**

- 一次周测（10 题，短）。
- 画像重新推断一次，有变化才提示确认。

## 8. 界面

界面只有一种语言：中文。英文只出现在学习内容里，并且用衬线体和界面文字分开——看的是哪种文字，一眼就该知道。

### 主面板：四视图工作台

顶栏一行：标题、四个视图（今日 / 单词 / 计划 / 个人）、右侧状态（待复习、连续天数、档位）和测评入口。内容区左右两栏：左边是当天的正事，右边一栏常驻复习卡。

| 视图 | 回答的问题 | 左边 | 右边 |
|---|---|---|---|
| 今日 | 今天我学什么 | 课程（逐项展开）+ 今日进度条 | 复习卡 + 本周目标 |
| 单词 | 我手上到底有哪些词 | 词库：全部 / 在学 / 已掌握 | 复习卡 |
| 计划 | 我这周走到哪 | 三个阶段的时间线 | 本周目标 + 换路线 |
| 个人 | 我想学什么、练到哪了 | 个人目标与兴趣编辑；下方四个数字 + 水平曲线 | 下方档位与参照 + 薄弱项 + 诊断 |

个人页的目标、每日时长、目标档位、具体目标和兴趣统一保存；编辑过程中轮询不会覆盖输入，保存失败保留草稿。兴趣支持回车、逗号或「添加」，直接保存也会收录尚未添加的输入，最多 12 个。今日右栏标题改为「单词学习」，包含复习和新词；悬浮层「打开主页」返回今日页。

复习卡是同一个组件，两个视图里都是它：词（衬线大字）、四个中文释义、`1`–`4` 直接选、`↵` 下一张；答完立刻给释义和讲解，盒子（1–5）和「第 n / N 个」就在词旁边。

**课程卡片是折叠的**：一行一项（类型、标题、时长、完成勾），点开才展开正文。默认展开第一个没做完的项——「继续这一课」只需要一次点击，而不是先找到它。

**词库不是「到期数」**。没有词到期的日子，词库照样列出手上的每个词、它的盒子和下次时间；复习卡说明「今天没有到期的词 / 下次 10 月 21 日 · 3 个」。只看一个 `0` 会让人以为没东西可学。

**词库点得开**：点一行只看四件事——释义、讲解、下次复习、作答次数与失误。盒子、来源、加入时间这些不放进弹窗：它们要么能在词库里一眼看到，要么不该占用注意力。

**课上的卡片先挡住答案**：正面是问题，点一下才展开背面和讲解。先看到答案的卡片等于没问。

**一次学 10 个**：设置里的「每天学几个词」（默认 10）同时决定课程出几个词和一次复习抓几个。当天的词学完、还有剩的就接着复习；一个不剩了就「继续学习」，让 Agent 再补一批。

### 悬浮层：碎片时间的复习台

药丸显示待复习数，点开就是一张卡：词（衬线大字）、四个中文释义、点选作答，答完当场给释义和讲解，然后「下一个」。一轮按「每天学几个词」抓，答完还剩下多少就是「继续复习剩下的 n 个」，一个不剩了是「继续学习」——不必回面板。收起再打开接着没答完的那一轮，不会从头开始。

面板里那套复习卡照旧；两边答的是同一个队列，谁答完都通知对方重读一次。词库、长文、课程仍在面板里：悬浮层只有 306px 宽，小到只够放一张卡，长得看不了正文，这也正是它适合碎片时间的原因。

### 设置页

每天学几个词、生成时间点、音频来源、数据目录、自动化开关（**默认关闭**，见 §10）。宽度收在 760px，不跟着窗口拉开。

## 9. Agent 工具

只有五个。少是为了让提示词与调用路径都短。

| 工具 | 方向 | 作用 |
|---|---|---|
| `english_state` | 读 | 一次取回画像、大纲、水平估计、到期复习数、已有词表、近 7 天已用素材 |
| `english_save_lesson` | 写 | 提交一堂课的结构化内容（含素材来源与卡片），校验后落盘 |
| `english_save_assessment` | 写 | 提交一整套测评题 |
| `english_add_words` | 写 | 补充词汇：加入复习队列、立刻可学；与已有词重复的会被跳过 |
| `english_record` | 写 | 记录作答、完成状态、掌握变化 |

**为什么读也做成工具**：Agent 在无人值守会话里跑，没有任何上下文；让它通过一个工具一次拿到全部状态，比让它读六个文件更短、更不容易出错，也避开了工作区沙箱。

## 10. 每日任务的执行

1. 用户开启自动化后，插件创建一个专用会话（`cwd` = 数据目录），并 `ctx.schedule.create` 一个 daily 规则。
2. 投递时，会话里的 Agent 收到一段固定提示：先 `english_state`，再搜索、筛选、加工，最后 `english_save_lesson`。
3. 幂等：投递是至少一次的，`english_save_lesson` 以日期为键，同一天重复提交只覆盖不追加。
4. 关着应用的那几天不补——只在下次打开时由调度服务补最近一次。这是平台约束，不试图绕过。

**提示词里写死的验收标准**（不满足就换源，不允许编造）：

- 必须有可访问的原始链接；
- 必须是最近 30 天内发布；
- 必须没有被过去 7 天用过；
- 阅读 200–350 词，听力 3–5 分钟文稿；
- 抓不到就换源，并写明换了什么、为什么。

## 11. 水平评估

**结构**：20 题，自适应——从中间难度起，答对升级、答错降级。其中 3 道来自锚题库，混入且不标记。

**水平估计怎么算**：不是答对率，而是**答对题目的难度加权均值**。答对一道 B2 的题，比答对三道 A2 的题更能说明问题。答对率会同时保留，作为诊断信息。

**锚题的作用与它的失效模式**（这一条必须写清楚）：

锚题是用来发现"模型生成题目的难度在几个月里漂了没有"。它有一个致命弱点：**同一个学习者反复见到同一道锚题会记住它**，记住之后答对反映的是记忆而非能力，锚题就失效了。

对策，按可靠性排序：

1. **锚题库比单次用量大**：12 道，每次测评抽 3 道轮换。
2. **只采信首次暴露**：同一道锚题的重复作答标记为污染样本，不用于漂移判断。
3. **不自动校正分数**：样本量太小，自动校正会把噪声当信号。锚题连续 3 次显著偏离基线时，只在曲线上标注一句"近期测评难度可能不稳"，不改动曲线本身。
4. **承认它只是粗检**。单学习者、12 道锚题的规模，能发现的是"整套系统明显变松或变紧了"，不是精细漂移。

**显示映射**：内部六级量表 → 六个中文档位。档位参照只在首次测完和每次测评后出现，不常驻。

**为什么不显示内部量表名称**：它在中文语境里没有直观意义，还会让人误以为这是张证书。

## 12. 复习与掌握

- 复习对象是**单词与整块表达**，整块优先——"Could you clarify that point?" 比 "clarify" 值钱。
- 间隔：1 / 7 / 30 / 90 天。
- 答题形式与测评一致：四选一。这样对错信号客观，盒子才推得动。
- **掌握** = 在 1、7、30 天三个间隔上各答对一次。之后 90 天抽检。
- 自评"认识/不认识"**不用**。人会看错自己的记忆，这是间隔重复系统最常见的死法。

**到期按自然日算**：间隔以天为单位，不按钟点。昨天上午 11 点答过的词，今天早上 8 点就到期，而不是熬到 11 点——按钟点比会把新的一天挡在门外，药丸上还写着"下次 10 月 21 日"，明明就是今天。代价是深夜 23:50 答完的词，第二天 00:00 就算到期；对每日节奏的学习来说，这比"必须等到昨天的同一分钟"更贴预期。

**第一次见面的不算复习**：新词当天就到期，但第一次作答只是"认识一下"——只排出 1 天后的复习，不推盒子。否则 1 / 7 / 30 这条链会从第 0 天开始，掌握就虚了。

**今天的词就是今天这节课的词**：课程保存时，它要教的那组词直接进队列、当天到期。所以面板和悬浮层抓到的第一批新词，和课上的词是同一组；想再多学，才是「继续学习」起 `vocab` 任务另出 10 个。这节课还没生成的日子，队列里没有课上的词，「继续学习」第一个出词也成立。曾经课上十个词排在明天，当天队列是空的，一按「继续学习」就生成另外十个——一天两组词，谁也不认识谁。

**"继续学习"从哪来词**：当天到期的词学完、词库又不够时，按钮会起一个 `vocab` 任务，让 Agent 按画像和当前档位再出 10 个新词（可用 `english_add_words` 提交）。这批词立即到期，出好后自动接上，不打断复习惯性。每天学几个由设置里的「每天学几个词」决定，课程生成和补充学习都按这个数。

**碎片卡的预生成**：卡片在每日任务里与课程一起生成，点击零延迟、零成本。碎片时间不能用来等加载，也不该每点一下花一次钱。

## 13. 音频

一个 `AudioProvider` 接口，三个实现，首版只做第一个：

| 实现 | 状态 | 说明 |
|---|---|---|
| `web-speech` | 首版 | 浏览器自带语音合成。全平台、零依赖、无 key。音色取决于系统 |
| `source-audio` | 后续 | 素材自带音频时直接用，最真实 |
| `external-tts` | 可选 | 用户自己配 key，音质更好 |

选接口而不是直接写死一个方案，是因为"机器朗读"和"真人声音"对听力训练的价值差很远，将来一定要能换；而换的成本全在接口设计上，现在不做就是以后重写。

## 14. 合规

- **锚题自制**（ADR-0002）。不抓取任何考试机构的题目，不从受版权保护的文本衍生题目。
- **没有内置词表**。补充词汇由 Agent 按画像和档位出词，插件只做校验、去重与排期。曾评估 CEFR-J（需在 NOTICE 给出指定引用）与 Octanove 的 C1/C2 表（CC BY-SA，传染性），首版均未采用；将来若引入，单独成文件并标注。
- **素材保留出处**。每份被采纳的阅读与听力都记录原始链接、抓取时间与许可说明。
- **不暗示关联**。界面上不出现任何考试机构名称作为背书；档位参照只说"大致相当于"。

2026-10-20 用一个一次性探针插件实测。四条已确认，一条待验证。

| # | 问题 | 结果 | 结论 |
|---|---|---|---|
| 1 | 插件写工作区外文件的权限 | `ctx.fs` **拒绝**（`workspace-write` 拦下）；`node:fs` **成功** | 插件用 `node:fs` 写数据目录，见 ADR-0001 |
| 2 | 调度能否冷启动会话 | **能**。创建会话（不激活）→ 120 秒后投递 → 完整跑了一轮并回复 | 每日任务机制成立 |
| 3 | 权限预设 `never` 的含义 | 未测 | 实现前仍需确认 |
| 4 | 会话 `cwd` 能否在工作区外 | **能**。会话按 `cwd` 分组存放 | 每日会话可直接扎在数据目录 |
| 5 | `shell.overlay` 能否挂载 | **能**。组件渲染并回调了 Host 路由 | 悬浮层方案成立；视觉层级待人工确认 |

实测还带出两条设计输入：

- **会话的 `cwd` 会成为该会话自己的沙箱边界**。每日会话扎在数据目录后，Agent 在那个目录里的写入是合法的——但这不改变 ADR-0001 的决定，理由见该 ADR 的修正。
- **`ctx.timer` 需要声明 `inject: ['timer']`** 才能用，否则在 `apply` 里访问会抛错。每日任务不依赖它（用 `ctx.schedule`），但任何轮询都要记得声明。

### 实现验收（2026-10-20）

插件装进真实 profile 后，以下路径是**跑通过的**，不是推断：

| 路径 | 实测结果 |
|---|---|
| 安装与展示 | 插件列表有中文名与描述；侧边栏、主面板、设置页、悬浮层四个槽位都注册为 active |
| 生成测评题库 | 点一次 → 冷会话被投递 → Agent 跑完一轮 → `english_save_assessment` 落盘 24 题（难度 1–6 各 4 道） |
| 测评 | 走完 20 题自适应；产出「中级」+ 参照 + 薄弱环节；曲线追加一个点；锚题基线写成 1.0 |
| 大纲 | 首次测评完成后自动生成三阶段，无日期 |
| 生成今日课程 | 一次真实运行抓到 Newsweek 与 NPR 两篇素材，落成草稿（阅读 275 词、听力文稿 755 词、3 条表达进复习队列、2 张碎片卡） |
| 完成课程 | 逐项完成 → 状态 draft→active→done；完成日期进入进度；复习队列 3 项当天到期（第一次作答只排 1 天后的复习） |
| 每日自动 | 开启后创建 daily 调度，关闭后调度被删除；默认仍是关闭 |
| 工具回传 | 提交缺字段/缺素材的课程被拒绝并返回 `code` 与 `field`，数据目录不变 |
| 领域测试 | `node --test test/core.test.js` 34 项全绿 |

跑通过程中改掉了三处实现错误：

- 锚题池第一次读取时只走了内存默认值，没有落盘——`anchors/items.json` 必须显式写一次，否则「冻结 + 哈希」实际上不存在。
- 每日调度的 `time` 必须是 `HH:mm:ss`，而设置页收的是 `HH:mm`；不补秒会让 `schedule.create` 静默失败。
- 碎片卡可能没有选项（Agent 只写了正面与释义）；这类卡要么从同名复习项借选项，要么丢弃并给出警告，否则药丸里会出现一张点不动的卡。
- **冷启动时 `webServer` 可能还不存在**。装插件是热加载（服务都在），重启客户端是冷启动（插件可能先于 web server 激活）。此时 `ctx.get('webServer')` 返回 `undefined`，原来的 `if (webServer)` 会静默跳过路由注册——表现是重启后插件面板打不开，而重载一次插件就好了。现在改成等服务出现再注册，而不是跳过。
- **悬浮层里的 `position: fixed` 不一定相对视口**。宿主层若有 transform，`fixed` 会相对那一层解析；那一层在非插件页是零尺寸，于是药丸跑到左上角压住按钮。现在外边套一个显式 `100vw × 100vh` 的层，药丸相对它定位。
- **每个根组件都要自带样式表**。样式原来是作为 `<style>` 元素渲染在面板里的，离开插件页那棵树就没了——药丸在会话页变成没有定位的裸 div，于是"固定在左上角、拖不动"。这不是定位问题，是样式没加载。现在悬浮层自己也渲染一份 `<Style>`；三个根各自独立正确，重复的那几 KB 无所谓。

规格复查又找出六处「写了但没写对」，每一处都补了测试：

| 问题 | 后果 | 现在的行为 |
|---|---|---|
| 漂移判断把污染样本也算进去 | 锚题一旦被记住，第二次答题反而会推动漂移告警 | 只有首次暴露参与；本次全是污染样本时该点不给锚题准确率，漂移状态不变 |
| 复习项不等到期就能答 | 同一天连点三次就能得到「掌握」，间隔失去意义 | 未到期直接拒绝（`not_due`）；药丸本来就只出到期项 |
| 过期的草稿还能被点开完成 | 「草稿不计入进度」被绕过，昨天没学的课今天还能算 | `lesson.start` / `lesson.completeItem` 遇到过期草稿直接拒绝并把它标为过期 |
| 改了生成时间点，调度不更新 | 设置里改了时间，实际生成时间不变 | 时间或时区变了就删旧建新，并把 key 记进 `jobs.json` |
| 重复提交把素材出处又追加一遍 | 同一份素材在 `provenance.jsonl` 里出现多次 | 按日期整段替换 |
| 同一套题库反复出同一批题 | 学习者可以背题刷分 | 优先出上次没出过的题，并轮换同难度候选中取哪一个 |

另外补了两条规格要求但原先没有的：

- **表达自动进复习队列**：Agent 只交了表达、没交复习项时，插件用同一课里其他表达的中文释义做干扰项，就地生成四选一；不足四条表达时不做，而不是出一张两个选项的卡。
- **画像按工作区猜一版**：首次引导会读最近一个会话的工作目录（`package.json` 的描述优先，否则用目录名）预填「你在做什么」，由使用者确认或改掉——它只是表单预填，不会背着人写盘。

以及一条规格里没写、但实现时不得不明确的：**只有到期才能推进盒子**。这不是加规则，而是「掌握 = 在 1、7、30 天三个间隔各答对一次」的另一面：如果不到期也能推进，这三个间隔就不再是间隔。

**2026-10-20 第二轮：界面重排**

| 问题 | 后果 | 处置 |
|---|---|---|
| 界面跟着系统语言走 | 系统是英文，整个面板被翻成英文 | 去掉语言检测，固定中文；英文只留在材料里（衬线体区分） |
| 单词只在药丸里学 | 药丸成了主入口，主面板只剩一个「到期 0」 | 单词成为主页的一等视图：词库 + 复习卡，面板拥有答题 |
| 只显示「到期数」 | 没有词到期时，看不出手上还有哪些词 | `review.list` 给出全部词、盒子、下一次到期；词库照常列 |
| 课程正文一次性铺开 | 五项的正文连成一面墙 | 课程改为折叠行，默认展开第一个没做完的项 |
| 药丸和面板共用答题逻辑 | 两处推进同一个盒子，进度可能对不上 | 两边都能答，同一个队列、同一个 `review.answer`；任何一边答完，另一边重读（见 §8） |

这条先走过弯路：第二轮把药丸收成了纯入口，结果新的一天在药丸里点开只剩「在面板里复习」。碎片时间本来就该能答——**入口和台面是两件事，药丸可以两个都是**；真正要防的不是"两处能答题"，而是"两处各存一份进度"，所以两边都只存界面状态，盒子只在服务端动。

排版原型（三个结构不同的方向）留在分支 `prototype/ui-layout`，主分支只保留选定的「工作台」。

**仍未由人眼确认**：新排版在真实窗口里的观感、暗色主题、药丸在别的会话里的观感。这些只能由使用者在界面上看一眼。
