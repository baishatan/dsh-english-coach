# 学习者数据由插件落盘，不由 Agent 落盘

学习数据存放在用户主目录下的固定位置（默认 `~/DeepSeek-English/`），而这个位置在 DSH 默认的工作区沙箱之外。

我们的做法是：**Agent 只负责调研与产出结构化内容，通过插件提供的工具回传；写文件这件事由插件自己的 Host 代码完成。** Agent 一个文件都不写。

> 2026-10-20 实测修正：本 ADR 最初的理由是"Agent 在无人值守时会因为沙箱而写不出去"。这个理由**部分不成立**。实测发现，会话的 `cwd` 可以设在任意目录，且该目录会成为这个会话自己的工作区边界——把每日会话的 `cwd` 设成数据目录后，Agent 在那个目录里写入是合法的。因此沙箱不再是这个决策的理由。

理由修正为下面三条，任何一条单独看都仍然成立：

1. **单一写入路径**。数据只有一个入口，schema 校验、版本迁移、幂等覆盖都只需要实现一次。
2. **幂等可控**。调度投递是至少一次的，同一天可能被投递两次。由插件按日期为键覆盖写入，比依赖 Agent 每次都不重复写要可靠。
3. **可发布的安全性**。别人装了这个插件时，不必为了让它能干活而放宽任何会话的沙箱边界。

实测的另一半结论很重要：**插件代码不能通过 `ctx.fs` 写工作区之外的文件**（会被 `workspace-write` 策略拒绝），但**可以通过 `node:fs` 写**。这是一个刻意偏离受管路径的选择——插件本身就是用户批准安装的受信代码，`ctx.fs` 的沙箱是为 Agent 工具调用设计的，不是为插件自身设计的。

代价：插件的数据层必须自己撑起 `node:fs` 的直接读写，包括原子写入（临时文件 + rename）和损坏恢复。这部分不能指望平台代劳。
