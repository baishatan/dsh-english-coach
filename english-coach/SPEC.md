# 英语教练 · 规格

> 术语以 [GLOSSARY.md](GLOSSARY.md) 为准；设计理由见 [DESIGN.md](DESIGN.md) 与各 ADR。本文只写"要做什么"与"怎么判定做对了"。

## 问题陈述

学习者面临的问题不是没有英语材料，而是**每天不知道该学什么**：找到一篇难度合适的文章要翻好几个站、确认没学过要翻记录、抠出值得记的表达又要一遍、排复习要靠自制力。这套准备工作每天吃掉二三十分钟，而真正用于读和听的时间被挤压到所剩无几。结果是收藏夹越来越长，能力原地踏步。

更具体的失败模式：

- 难度靠猜，太难的挫败、太简单的无聊，两边都会让人在两周内放弃。
- 复习没有排期，遇到过的表达不会被再次遇见，所以记不住。
- 学什么全凭当天的兴趣，一个月后回看，没有任何可以比较的进步证据。
- 想利用碎片时间复习，但每次都要先打开一个 App、找到入口、点进词表——三秒钟的摩擦足以让人放弃。

## 方案

一个安装在 DeepSeek Harness 里的常驻插件，围绕一个学习者运转，每天自动完成准备工作，并把学习拆成两种场景：

- **长内容在主面板**：一天一节课，约 30 分钟，逐项完成。
- **短内容在悬浮层**：一个可收起的药丸，点开是一叠碎片卡，两三分钟清理一批到期复习。

水平判断用一次约 10 分钟的选择题测评，产出一个中文档位和一个可比较的水平估计；路线用一份只写阶段目标、不写死日期的大纲；每天的素材由 Agent 按画像与近期工作方向搜索、筛选、加工，落成一份**草稿**，学习者点开才算开始。

## 实现决策

1. **两部分**：Host 半负责数据、调度、工具；Client 半负责主面板三视图、悬浮层与设置页。两者只通过 Remote 方法与工具通信。

2. **数据所有权**：所有写入由插件的 Host 代码完成，Agent 不写文件（ADR-0001）。写入必须原子化（写临时文件后 rename），并能在文件损坏时回退到上一个可用版本。

3. **写入路径**：插件使用 Node 的文件接口直接读写数据根目录，**不使用**受管的文件服务——后者会把工作区之外的写入拒绝掉（已实测）。这是一处刻意偏离受管路径的选择。

4. **数据根**：用户主目录下的固定子目录，可在设置里改。四个逻辑存储：画像与设置、水平估计与历史、复习队列、课程与素材来源。锚题单独存放且只读。

5. **Agent 工具（五个）**：
   - `english_state`：一次返回画像、大纲摘要、最新水平估计、到期复习数量、近 7 天已用素材标识。只读。
   - `english_save_lesson`：提交一堂课的结构化内容（含素材来源、学习项、碎片卡）。以日期为幂等键，重复提交覆盖不追加。校验失败返回结构化错误而不是抛异常。
   - `english_save_assessment`：提交一套测评题（含锚题标记）。同样以版本为键幂等。
   - `english_add_words`：补充词汇，加进复习队列当天可学；与已有词重复的跳过，选项与答案同一性由插件校验。
   - `english_record`：记录作答结果、课程完成状态、掌握变化。批量提交，按项去重。

6. **工具结果形状**：五个工具都返回同一形状——`{ ok: true, data, warnings }` 或 `{ ok: false, code, message, field? }`。不抛异常，让 Agent 能读到失败原因并自行修正。

7. **每日任务的绑定**：创建一个专用会话，`cwd` 设为数据根（已实测这样可行且会话会按目录分组）；用调度服务的日频规则把固定提示投进该会话。会话不归档（ADR-0003）。幂等由决策 5 保证。

8. **无人值守的工具面**：每日会话中的 Agent 只使用读状态、web 搜索/抓取、以及上述三个写工具。这三个写工具是插件自己的工具，不经过需要人工审批的路径。不要在该会话里使用需要审批的工具。

9. **水平估计的算法**：一次测评的原始水平 = 答对题目的难度加权均值（不是答对率）。答对率单独保留作诊断。每个测评结果作为历史曲线上的一个点追加，不删除旧点。

10. **锚题**：池 12 道，每次测评取 3 道，混入且不标记。只采信每道锚题的**首次暴露**；重复作答标记为污染，不参与漂移判断。锚题连续 3 次显著偏离基线时，仅在曲线上加一句提示，**不自动校正分数**。锚题冻结、记哈希、只退役不修改（ADR-0002）。

11. **显示映射**：内部六级量表映射到六个中文档位。界面、提示、错误信息、工具描述中一律不出现该国际分级框架的名称。档位参照只在首次测评后与每次测评后出现。

12. **复习算法**：Leitner 盒子，间隔 1 / 7 / 30 / 90 天。答对推进一盒，答错退回第一盒。掌握 = 在 1、7、30 天三个间隔各答对一次。不用自评"认识/不认识"。

13. **碎片卡分工**：悬浮层只渲染短内容（复习、测验、排序题），任何长文都只在主面板渲染。悬浮层在长内容处给一个跳转入口。

14. **课程状态机**：草稿 → 进行中 → 已完成；当天结束仍未开始的草稿转为过期。进度统计只认完成态。

15. **素材来源记录**：每份被采纳的阅读或听力都必须带原始链接、抓取时间、许可说明。缺少任何一项的课程拒绝落盘。

16. **音频抽象**：一个"把英文文本变成可听声音"的接口，首版只有一个实现——浏览器的系统语音合成。接口必须允许后续加入"素材自带音频"和"外部语音服务"两种实现，而不改动调用方。

17. **四个视图**：今日、单词、计划、进度。设置从独立的设置分区进入，不占主面板视图。复习卡在两个视图里复用同一个组件，答题只在面板里发生。

18. **自动化默认关闭**，开启后才有调度器；关闭时保留已有数据不动。

19. **界面固定中文**：不跟随系统语言。英文只出现在学习材料里，用衬线体与界面文字区分。插件列表里的标题与描述必须有实际意义，不能留模板文字。图标原创。

20. **首次测评不依赖任何密钥**：题目由本机已配置的模型生成，不向用户索要第三方凭证。

21. **补充学习也是 Agent 任务**：没有内置词表。缺词时起一个 `vocab` 任务，Agent 按画像、档位和已有词表出词，用 `english_add_words` 提交。插件只负责校验、去重、排期，不负责编造。

22. **每天学几个词是一个设置**（默认 10，范围 3–30）：课程生成、补充学习、一次复习的条数都用它，避免三处各有一套数。

## 测试决策

**只设一条缝**：一个纯 Node 的领域与状态模块。五个工具的处理逻辑、面板用到的读写、调度任务落盘，全部穿过它。测试只打这一层。

- **测什么**：给定一个临时数据目录和一个命令，断言"返回的结果"与"目录里最终的状态"。只测外部行为，不测内部函数怎么拆分。
- **不测什么**：不测 Host 的 `apply`、不测 Remote 通道、不测 React 组件、不测 Harness 的调度器本身。这些是平台行为，已经用一次性探针验证过（见补充说明），重复测试只会重复维护成本。
- **关键用例**（都属于外部行为）：
  - 同一日期提交两次课程 → 最终只有一课，且内容是第二次的。
  - 复习项答对三次（分别在 1/7/30 天间隔）→ 状态变为掌握；任一环节答错 → 回到第一盒。
  - 提交缺素材来源的课程 → 拒绝，错误指明缺哪个字段，目录不变。
  - 测评结果追加 → 历史点增加一个，旧点仍在，曲线顺序正确。
  - 锚题重复暴露 → 第二次的计入作答但标记污染，不进入漂移统计。
  - 数据文件被人为截断 → 读取回退到上一个可用版本并给出警告，不崩。
  - 过期草稿 → 状态转过期，不进入已完成统计。
- **先例**：本仓是全新项目，没有既有测试可参照。测试运行器用 Node 自带的测试能力，不引入额外依赖。

## 不在范围内

- 口语与发音评分。
- 图片生成、视频生成、以及任何需要第三方付费生成服务的多模态。
- 多账号、多学习者、家庭共享。
- 社交、排行榜、打卡分享、证书。
- 与任何外部考试分数的等价换算或分数换算表。
- 跨设备同步（数据可被用户自己拷走，但插件不做同步）。
- 补跑多天：关机期间漏掉的天数只补最近一次，不逐日生成。
- 在对话流内渲染自定义工具卡片。
- 无障碍与键盘操作的完整覆盖（首版只保证基本可用）。

## 补充说明

**probe 证据（2026-10-20）**

设计中有五条假设会影响成败，其中四条用一次性探针插件实测过：

- 调度投递可以让一个从未被打开的会话跑完一整轮并回复——这是每日自动化的地基，已确认。
- 会话的 `cwd` 可以设在任意目录，且该目录会成为该会话自己的工作区边界，会话也按该目录分组存放——已确认。
- 插件用受管文件服务写数据根目录**会失败**，用 Node 文件接口**会成功**——已确认，因此有了决策 3。
- 悬浮层可以挂载，组件能渲染并回调 Host 注册的路由——已确认到"渲染"这一层；**它是否真的浮在最上层、是否遮挡其它控件，尚未由人眼确认**。

**仍未验证**

- 权限预设中"从不询问"的语义究竟是自动放行还是全部拒绝。决策 8 通过让无人值守会话只使用无需审批的工具来绕开这个不确定性；如果将来需要放宽，必须先测这一条。

**实现验收（2026-10-20）**

插件已装进真实 profile 并跑通以下端到端路径，明细见 [DESIGN.md](DESIGN.md) §15：

- 生成题库 → 20 题自适应测评 → 档位与大纲 → 生成真实课程 → 逐项完成 → 复习队列排期 → 每日调度开关。
- 领域层 35 项测试全绿（`node --test test/core.test.js`），覆盖本文「测试决策」中列出的全部关键用例，另加 `review.list`（词库、到期标记、下一次到期）一条。

**界面改版（2026-10-20）**

- 界面固定中文，不再跟随系统语言；英文只出现在材料里。
- 主面板改为四视图工作台，单词回到主页：词库 + 复习卡，两侧视图复用同一个复习组件。
- 悬浮层降级为入口：数量 + 下一个词 + 「在面板里复习」，不再答题。
- 排版原型（三个方向）留在分支 `prototype/ui-layout`，主分支只保留选定的工作台。

**仍未由人眼确认**

- 新排版在真实窗口里的观感（卡片密度、右栏宽度、暗色主题）。
- 药丸在别的会话里是否仍然好找、不碍事。

这两条只能由使用者在界面上确认，代码与槽位注册通过不等于看到了正确结果。

**一处待清理**

探针在数据根目录留下的 `_probe-node.txt` 已在实现自测时随目录一起清掉。侧边栏里那个探针生成的会话仍在，可在会话列表里自行归档。

**风险**

- 素材可达性随网络环境变化。已确认 BBC Learning English 与 VOA 可达，British Council LearnEnglish 从当前网络不可达。决策 15 与提示词中的验收标准共同保证：抓不到就换源，不编造。
- 每日任务每次都是一整轮模型调用（含搜索与工具调用）。首版不设额度上限，但自动化默认关闭，且生成物先落为草稿。
